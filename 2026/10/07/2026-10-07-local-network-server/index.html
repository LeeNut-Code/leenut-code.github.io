无宽带也能搭家庭服务器：4G 随身 WiFi + 旧 NUC 的本地网络方案

家里没有拉宽带，手上有一张 4G 卡和一台吃灰的旧 NUC，于是干脆用随身 WiFi 当出口、旧路由器当中继、NUC 当服务器，搭了一套完整的家庭网络：NAS 共享、Docker 服务、DNS 分层、代理出口全都有。本文记录这套网络的结构和搭建过程，以及踩过的坑。

各设备分工

设备 IP 角色
随身 WiFi（PLERY，COMFAST 贴牌） 192.168.43.1 出口。4G LTE FDD，广电 192 号段，固件是「4G Hostless Modem」类型（ZTE 方案），内置 DNS（53 端口），带电池
小米路由器 R4AC 192.168.43.2 中继。无线桥接随身 WiFi，自己再广播 SSID「UEI-WIFI-wan」（2.4G + 5G）
家庭服务器 SPC 192.168.43.136（有线，主）/ 192.168.43.132（无线，备） DHCP 服务方、DNS（SmartDNS）、Samba/NAS、Docker 服务栈
笔记本电脑 192.168.43.63 日常主力机（Arch Linux），DNS 走本机 AdGuardHome
手机 192.168.43.152 普通客户端

服务器是 Intel NUC（CRESCENTBAY），跑 Debian 13 (trixie)，7.7G 内存：111G SSD 做系统盘，465G 的 HGST 机械盘做数据盘。有线和无线双链路都配了静态 IP，有线优先（metric 默认）、无线备用（metric 600）——有线断了自动切 WiFi。

顺便说一句，随身 WiFi 这个东西本质就是一块带电池的 4G 模组 + 路由固件，管理后台的接口（/reqproc/proc_post）和 ZTE 的 goform 族一脉相承，用命令行直接调接口比网页后台方便得多，后面会提到。

寻址与 DHCP：服务器统一管理

所有设备的 IP 都是固定的，但实现方式分两层：

  • 服务器、笔记本、手机、小米路由这些”自己人”用静态配置或 DHCP 保留；
  • 来宾/临时设备走 DHCP 地址池。

DHCP 由服务器上的 dnsmasq 负责（只做 DHCP，不做 DNS，所以 port=0）：

几个要点：

  • dhcp-authoritative：这个网络里只有这一个 DHCP 服务方，客户端不用等旧租约过期；
  • dhcp-option=option:router 把网关指回随身 WiFi（192.168.43.1），服务器自己不做转发；
  • dhcp-option=option:dns-server 把 DNS 指向服务器自己（.136/.132），这样来宾设备连上来就自动用上 SmartDNS；
  • 地址池 192.168.43.160–250，12 小时租约，和固定设备的地址完全错开。

DNS 分层：SmartDNS + AdGuardHome

DNS 没有只做一层，而是按设备分了两套：

服务器：SmartDNS（Docker）

  • 上游主用 Cloudflare Gateway 的加密 DNS（DoH/DoT），备 tls://223.5.5.5 仅在主不可用时启用；
  • spc.local 这类本地域名直接映射 IP，局域网内不用记 IP；
  • 自带仪表盘插件，http://192.168.43.136:6080 可以看查询日志。

然后服务器的 /etc/resolv.conf 指向 127.0.0.1 和 ::1，并 chattr +i 锁住防止被覆盖——这一步很关键，后面踩坑里细说。

笔记本：AdGuardHome

笔记本的 DNS 查询由部署在本机的 AdGuardHome 负责（53 端口），上游同样是加密 DNS，fallback 阿里 DoT。好处是本机能看查询日志、加过滤规则，而且不受网络切换影响（换网络不用改 DNS 配置）。

两套 DNS 的上游一致，所以解析结果在全网是一致的；区别只是本机多了过滤和日志能力。

存储 / NAS：ntfs3 + Samba + 自动挂载

数据盘挂载

465G 机械盘是 NTFS 格式（还要兼顾 Windows 直插），用内核 ntfs3 驱动挂载（性能比 ntfs-3g/fuseblk 好很多）：

windows_names 这个选项是 SMB 共享 NTFS 盘的关键——它保证文件名兼容 Windows（不允许 Windows 非法的字符），不然 SMB 客户端写入时容易出问题。nofail 防止盘故障卡开机。

Samba 共享

/etc/samba/smb.conf 加一个 [data] 段指向 /mnt/data，仅限 user 访问；[homes] 段（Debian 默认只读+隐藏）改成 browseable = yes、read only = no，这样每用户自动映射自己的主目录。

客户端自动挂载

笔记本这边 fstab 一行搞定：

选项 作用
credentials 密码从单独文件读（root 600），不出现在 fstab
x-systemd.automount + idle-timeout=60 按需挂载：访问 /mnt/SPC-data 才连接，60 秒无访问自动断开
soft + nofail 服务器不在线时开机不卡、不报错
x-gvfs-show / x-gvfs-name 文件管理器侧栏显示为「SPC-data」

⚠️ 配完不要用 mount /mnt/SPC-data 手动挂——会绕过 automount 单元导致它显示 inactive；用 systemctl start 'mnt-SPC\x2ddata.automount' 直接启动单元。

Docker 服务栈

服务器上跑的容器（全部 restart=always，开机/崩溃自动拉起）：

容器 镜像 端口 用途
smartdns pymumu/smartdns 53/udp + 6080 DNS + 仪表盘
v2raya v2raya/v2raya 2017 面板；7890/7891/7892 代理 代理出口
dpanel (lite) dpanel/dpanel:lite 8807 Docker 管理面板
sun-panel hslr/sun-panel 3002 导航页
openlist openlistteam/openlist 5244 网盘
jellyfin jellyfin/jellyfin 8096 媒体服务器

另外 nginx + Nginx-UI（:9000）用 systemd 二进制部署，跑了一个局域网 F-Droid 仓库（:2867，一百多个 APK，update-fdroid.sh 维护），给家里的安卓设备做应用源。

国内拉 Docker 镜像是个老大难，/etc/docker/daemon.json 里配了 19 个镜像加速源，实测一个挂了会自动换下一个。拉镜像失败的模式基本是”单层卡死/EOF”——这是上游的问题，换镜像源重试即可。

代理链路

笔记本

  • WARP：warp-cli 以 WarpProxy 模式跑在 127.0.0.1:40000（MASQUE 协议）；
  • Clash Party（mihomo）：mixed 端口 7890 / socks 7891 / http 7892，rule 模式，TUN 关闭。可以连洛杉矶的 VPS，也可以把 WARP 分享出去；

服务器

v2rayA 面板（2017）管理，socks/http/rule-http 三个 inbound 全绑 0.0.0.0，局域网内任何设备都能直接用 http://192.168.43.136:7890 当代理，出口走远程 VPS。

定时任务

  • 服务器每天 23:30 自动关机（root crontab：30 23 * * * /sbin/shutdown -h now）；
  • 每天早上 9 点用用户级 crontab 拉起两个随身 WiFi 自动化脚本（flock -n 防重入，守护常驻时跳过，崩溃后下次 9 点自动重启）：
    • battery-watch.py：电量监控守护；
    • enforce-cycle.py：定时执行 WiFi 配置维护。

随身 WiFi 的管理我写了一个命令行工具（Python 单文件，纯标准库），直接调设备接口实现登录/状态/流量/限额/WiFi 配置/MAC 过滤等，比网页后台省事得多。

踩坑记录

这部分是最有价值的，每条都是实际踩过的：

  1. ifupdown 的 wpa-roam 会卡死：Debian 上用 wpa-roam 配双 SSID，wpa_action 接管 ifup/ifdown 状态后，ifup 会循环失败（wpa_action is managing ifup/ifdown state），杀进程、删 pid 文件都没用。换 systemd-networkd + wpa_supplicant@wlp2s0 干净解决。
  2. /etc/cron.d 的定时任务不生效：文件在 cron 重启后写入可能不被监听。用 root 的 crontab（spool 方式）可靠。
  3. sudoers 语法：pwfeedback（密码显示星号）必须写 Defaults pwfeedback，裸写 pwfeedback 会报语法错导致 sudo 崩。
  4. 卸载 dhcpcd 会留空 resolv.conf：DNS 全挂。修复后记得 chattr +i /etc/resolv.conf 锁住。
  5. Docker 镜像单层拉不动：所有镜像源都卡在同一层 → 换 tag，或直连下载官方二进制本地构建。
  6. Java 容器内存限制：komga 用 512M 硬限会被 cgroup OOM 反复杀掉（重启 39 次）。正确方案是容器 --memory=1g --memory-swap=1g + JAVA_TOOL_OPTIONS="-Xmx512m -Xms256m"——堆封在 512M，元空间等非堆用剩余空间，总占用封在 1G 内。
  7. NTFS 盘共享给 SMB：挂载必须加 windows_names，否则文件名兼容性问题。
  8. SSH 首连新 IP 挂起：要确认主机指纹，脚本化时记得 -o StrictHostKeyChecking=accept-new。

总结

没有宽带也完全能搭一套好用的家庭网络：4G 随身 WiFi 当出口（配合流量限额防超），旧路由器当中继扩展覆盖，NUC 当服务器把 NAS、DNS、Docker 服务全扛起来。整个方案最值得投入的两件事：DNS 分层（服务端 SmartDNS + 客户端 AdGuardHome，全网解析一致还能过滤）和 DHCP 统一管理（固定设备保留 + 来宾池，来宾连上来自动用上内网 DNS）。剩下的就是踩坑攒经验了。
